## 可以照做的本机演示

在 Java 17、Maven、Python 可用的终端，从仓库根目录执行：

```sh
mvn -B -ntp -f server/pom.xml package
python3 scripts/run_synthetic_demo.py --port 18080
```

仅打开运行所在机器的 `http://127.0.0.1:18080/`，用公开本机演示账号 `demo-owner`。已有演示库保留；新建演示空间即可，不清空旧数据。启动器不读取 `.env`，只继承工具链白名单，固定 mock/回环地址。这里不是已建立的远端私有预览，不提供公网地址，也不承诺工作区销毁后的存储持久性。

1. 空状态“先新建工作空间”→创建原创人物→前往人格生成→沿用设定并单独确认授权。
2. 生成新候选→上传 UTF-8 `walkthrough.txt` 并返回；合成示例见测试源码的 `SOURCE`，不放入真人材料。提交生成→批准发布→绑定正确人物→返回。
3. 向下滚动到“我的交流”，点“新交流”发送问候；只把明确标记的模拟回答视作流程演示。
4. 到经历台“材料管理”选择同一 TXT→用所选材料生成知识→创建专题并提交→任务“审核发布”。人格材料不会自动变成工作知识。
5. 返回人物工作室，勾选已发布知识专题并保存；在“交流与记忆”先核对资料，提问“重试间隔是多少？”。
6. 点纠错链接后，再点经历台的“已审核知识”→编辑知识→保存并发布修订；返回重新提问，核对新内容和版本。
7. 受控阅读者只能看共享记录，不能读他人交流和材料原文。失权时以“当前资料/交流不可访问”状态为准；刷新人物列表更新最后读取的人物卡。

自动重复同一完整旅程（需要此环境已有 Playwright/Chromium，不安装或下载新依赖）：

```sh
python3 tests/first_text_walkthrough_e2e.py
```

该命令使用全新临时库并自行清理，不保留可登录服务。脚本中的合成令牌只是本机测试夹具，不能作为真实试用账户方案。
