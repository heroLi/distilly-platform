# 团队共享平台第一版需求

状态：第一版已实现并完成本地验收；内部部署验收待目标环境。基线：dot-skill / b830d3d。日期：2026-10-03。

## 目标与范围

让小团队将有授权的业务材料提炼成可审核、可追溯、可共享的工作经验。
第一版支持 UTF-8 Markdown/TXT 上传，Work-only 蒸馏，候选审核、发布与回滚，项目成员权限，网页问答、Skill 下载和操作审计。
保留已有本地创建器的兼容性。平台不采集本地 Agent 会话，不访问 Codex sessions，不自动采集私聊，不推断员工性格。
人物模拟、浏览器采集、OCR、向量检索、多人物协作及多租户企业治理不在本版范围。

## 用户与权限

用户属于项目，角色为 OWNER / EDITOR / VIEWER。
OWNER 管理成员、查看原材料和候选版本、审核发布、回滚；EDITOR 上传、创建蒸馏任务、查看原材料和候选；VIEWER 只能查看已发布经验、问答及下载。
所有资源访问由服务端检查所属项目与角色。客户端不可通过传递用户 ID 伪造身份。
本地演示模式使用显式启用的测试账号；内部试点使用预配置的个人访问令牌。令牌经哈希存储，Worker 使用独立凭证。企业 SSO 另行接入，演示模式不作为 SSO 验证。

## 核心流程

1. 创建项目并添加成员。
2. EDITOR 上传材料，选择经验 Profile，创建蒸馏任务；任务冻结材料 ID 与基础版本。
3. Worker 领取任务、分块分析、验证来源，写入候选工作知识。
4. OWNER 查看候选知识、来源证据、与已发布版本的差异；批准或拒绝。
5. 发布切换当前版本，旧版本不变。回滚切换到已发布历史版本。
6. VIEWER 提问时固定当前版本，仅将该版本的工作知识传给模型；回答附实际使用版本及可见来源引用。
7. 下载只导出 work Skill，不包含原材料、凭证、私人路径或 Persona。

## 数据与可靠性要求

- 原材料限制：单文件 1 MiB、单任务总文本 200k 字符，空内容、非法 UTF-8 与不支持类型明确拒绝。
- 知识条目包含稳定 ID、章节、内容、证据（material_id / chunk_id / 原文短片段）、状态。证据片段须存在于输入片段，无法验证的结论不得进入候选。
- 版本不可变，发布指针独立；并发发布使用基础版本检查，过期候选返回冲突。
- 任务有 lease、attempt、幂等完成、错误分类及重试上限；已发布结果不因失败被覆盖。
- 模型密钥只在 Worker 环境中配置；日志不得输出材料、令牌或模型响应正文。
- 来源文档是数据，不是可执行指令；模型不得执行上传内容中的命令。平台模型调用不赋予文件或工具执行权限。
- 保留项目操作审计；原始材料访问权限不因 Profile 发布而扩大。

## 验收标准

| 编号 | 场景 | 预期 |
|---|---|---|
| A1 | 同名本地创建 | 拒绝覆盖，既有文件不变 |
| A2 | 本地追加章节增量 | 保留旧知识；替换必须显式选择 |
| A3 | 回滚后再次更新 | 不复用历史版本，恢复元数据与内容一致 |
| A4 | 两个项目及不同角色 | 跨项目拒绝；VIEWER 无法读原材料、改版本 |
| A5 | 上传 → 蒸馏 → 审核 → 发布 | 网页及 API 完整闭环；候选默认不可共享 |
| A6 | Worker 故障 / lease 过期 / 重复完成 | 可恢复，受重试次数限制，不产生重复版本 |
| A7 | 无效证据、空材料、超限文件 | 明确失败，不发布无来源知识 |
| A8 | 追加材料及过期候选发布 | 新版本保留旧知识；冲突发布被拒绝 |
| A9 | 回滚及下载 | 历史版本不变；导出仅工作经验 |
| A10 | 问答 | 只使用已发布固定版本，信息不足明确说明 |
| A11 | 重启 | 项目、材料、任务、候选及发布指针持久保存 |
| A12 | 部署 | 提供启动、配置、健康检查、备份与恢复文档 |

验证分层：模拟模型验证协议与流程；HTTP 测试网关验证真实网络调用；企业模型验证回答质量；企业 SSO 和部署环境单独验证。未完成的层级必须明确记录。
