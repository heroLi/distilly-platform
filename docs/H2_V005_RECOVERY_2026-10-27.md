## 已证实原因与红测

H2 2.3.232 的 ALTER 会独立提交，包裹事务回滚不能撤销已完成的 DDL。原迁移器只在三条 V005 语句全部完成后记版本 5；在第一条后中断，列已存在而版本 5 缺失，重启重放第一条会报 Duplicate column library。

新的文件 H2 回归先运行原 schema/V001–V004、写入合成行，在事务中执行 V005 第一条后抛受控异常；关闭并重新打开数据库，再运行原迁移器。首轮红测确实报重复列，未构造假输出或重写原故障。日志 `data/resume-20261021/text-egress/v005-recovery-red-20261027.log` 保留。

## 最小修复边界

历史 SQL 文件一个不改，不使用 IF NOT EXISTS 或 continueOnError 泛化跳过。新增内部 `H2V005Recovery`，只在明确识别 H2 时使用；其他数据库继续原资源执行路径，未做真实 PostgreSQL 验证。

`2d810dfa1c52291942265a5542513657fee606c0b68fcd80623ee7b7a4799f4d`

只从该文件读取原三条 SQL。资源变化、增加第四条、未知表结构或元数据错误均停止，不猜测或修补。检查在本迁移器执行 DDL 前加载资源；不宣称能够阻止框架更早的基础 schema 初始化。

版本表仍保持 `(version, applied_at)` 两列，验证其结构和连续版本，无缺口或超出当前支持范围的版本。V005 缺失时，到达该版本必须已有且仅有 1–4；三列存在状态只能为原语句的前缀 `000 / 100 / 110 / 111`。非前缀或完成标记与实际结构不一致时明确拒绝。

恢复前后都核对当前 schema 内两张真实表的完整已知列集合、顺序和列定义，以及 PK/FK、引用范围/规则、索引、约束启用状态及触发器。包括长度、NULL、默认值、identity/generated、domain、on-update、default-on-null、可见性；额外列、约束、索引、触发器或同名 view 都不能被忽略。固定驱动执行原 SQL 的元数据是校验依据：其 TEXT 映射为 VARCHAR(1000000000)，不是 CLOB；upper/lower 标识符模式均覆盖。

只执行尚未完成的 SQL 后缀，不 UPDATE、DELETE、回填或覆盖业务行。完整后置条件复验通过，原迁移器才写版本 5。若执行中或版本标记前再次失败，已提交前缀仍可在下一次重新验证后续跑。已有版本 5 时只验完整结构，不重放、不更新时间；已有合规的版本 5及更高版本可正常继续。

这是单一迁移写入者、稳定连接 schema 下的 V005 合同，不是通用 DDL 修复器、并发 schema 锁或全库审计。并发手工 DDL、其他版本的部分迁移、未验证的驱动行为仍不在自动续跑承诺内。发生不匹配时应先只读检查和维护者审查，不清库、不自动删除对象，也不通过忽略异常强行启动。
