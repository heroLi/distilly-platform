## 删除长期记忆后的实际payload

通过现有Java任务/会话/记忆服务完成合成流程：提交用户事实→合成完成回调提议候选→用户确认→领取含记忆的在途任务→删除记忆→再次领取同会话与新会话任务。未运行Worker/模型，也未改写已有历史。

| 观察 | 实际结果 |
|---|---|
| 记忆主表 | 该记录已删除，后续memories区不再选入 |
| 原用户消息 | 仍保留 |
| 原在途任务 | CANCELLED，旧lease完成被409拒绝 |
| 同会话后续payload | memories无该记录，但history仍包含原用户事实；当前新消息本身不含该事实 |
| 新会话payload | memories无该记录，history无原会话事实 |
| 模型是否复述旧事实 | NOT_MEASURED，模型调用0 |

这说明“删除长期记忆”与“删除/屏蔽原交流历史”是不同边界。该测试是现状刻画，不是决定永久保留或自动删除历史；将来若产品合同改为全上下文不再使用，应保留本轮观察，新增合同/实现及新版本回归。此处不选择用户尚未决定的语义，也不将历史存在等同越权召回。
