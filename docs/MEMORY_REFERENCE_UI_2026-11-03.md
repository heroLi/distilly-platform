# 已确认记忆原文参考入口（2026-11-03）

## 使用路径与范围

登录后选择空间与人物，进入「交流与记忆」→「情感与关系记忆」→「查阅记忆原文（参考模式）」。打开弹窗不会发起查询；输入关键词并点击「查阅原文」后，才调用 `POST /api/personas/{id}/memory-references`。原有聊天入口、检索默认值及 Worker 协议保持原样。

弹窗与每张卡片明确标注「已确认记忆记录」「支持关系未判定」。正文是当前 SQL 已确认记忆，可能经过确认、纠错；不是原始聊天逐字记录，也不是模型回答。相关性不证明记录支持问题中的条件。此入口没有自由回答或流式片段，不调用模型，不创建聊天消息或任务。

## 页面契约与失效处理

- 仅接受 `MEMORY_REFERENCE_V1`、`SOURCE_REFERENCE`、`NOT_ASSESSED` 及已定义的记录字段；未知回答字段、重复 ID、错误指纹或状态拒绝展示。
- 正文、查询与元数据使用 `textContent`，不拼入 HTML。服务端错误正文不直接展示。
- 输入变化、关闭、切人物／空间／页面、退出及页面离开清除旧结果；进行中的旧成功或旧失败不会改变新一轮结果。选择人物未完成时禁用入口。查询与结果不新增持久存储。
- 请求开始先清除旧快照。空结果不表示事件从未发生。网络错误保留可编辑查询，允许手动重新核对；401／403／404 清空查询和结果。
- 已有记忆列表加载器观察到正文、来源、确认状态或存在性变化时清除已展示快照；本页记忆操作也触发失效。不会轮询此 API 或自动重新查询。
- 记忆列表在查询等待期间重新加载时，保守取消这一参考快照，需手动重新核对；即使列表内容没有变化也不接受该在途响应，避免以晚到快照覆盖已重新核对的状态。
- 这是一次读取快照，没有推送一致性保证。其他页面／设备的更新或撤权，须在现有页面刷新、记忆重载或手动「重新核对」时发现；已读取文字无法追溯收回。内容指纹不是单调版本号。

## 验证资产

`tests/memory_reference_ui_test.cjs`：26 个前端场景，覆盖显式入口、严格响应契约、HTML 安全、重复点击、输入变化、错误／失权／来源变化与生命周期竞态。新增等待期间列表重载场景先复现红测，再修复并验证。

`tests/memory_reference_ui_e2e.py`：原生 Chromium、独立临时 H2、loopback 服务及 mock Worker，9 组检查：真实 SQL 正文、无新增聊天／任务、1360×950 和 390×844 视口、空态、503 后重试、真实资料纠错、等待时列表重载、真实旧响应晚到、当前人物归档拒绝、切换与退出。503 为明确注入的浏览器错误夹具，纠错／归档及成功查询使用实际 API。脚本已加入标准入口末尾。

相关检查：

```sh
node tests/memory_reference_ui_test.cjs
python3 tests/memory_reference_ui_e2e.py
python3 scripts/verify.py --e2e
```
