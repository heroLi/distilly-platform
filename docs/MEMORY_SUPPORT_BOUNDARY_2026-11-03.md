# 召回候选、引用 ID 与事实支持的边界

基线 `d62345d2b837c834a2dc85c1941ad4cc2afedc5b`，分支 `resume/text-cost-gate-20261021`。本批核对既有 3 个 strict_support 开发负例的真实离线链路。只用公开合成开发资料和新增**回归**例，未构造封存集或声称盲测，未调用模型/外部服务。原规划草案及恢复证据保留。

## 已复现的事实

实际路径是 `SqlMemoryProvider → MemoryRetrieval → PersonaTaskService.claim → ContextAssembler → Worker persona.chat → PersonaTaskService.complete`：

- 默认词法召回仍会返回 D01-Q3、D02-Q3、D04-Q3 的相关来源，3/3 不变；它们并不支持问题指定的材料属性、实体或日期。
- Java 在装配和完成时复核用户、人物、确认状态和来源；Worker 校验输出引用属于输入 ID 集；完成接口再次校验引用属于领取时的来源集合。这些是来源身份、权限和生命周期检查，**不是回答蕴含/条件支持校验**。
- 原 mock 不判断问题条件，直接把第一条记忆加上“我记得你确认过”的前缀。即使来源仅相关或含否定，也会这样展示。此前没有候选/支持区分提示。
- 使用纯本地脚本响应（非模型、非网关请求），注入带有效 ID 的不受支持断言，实际 Worker 校验和 Java 完成接口仍会接受。本批明确保留该局限，不把返回 200/SUCCEEDED 当事实正确。

## 最小修复及未修复部分

只改 `worker/persona.py` 两处：

1. mock 保留原来源正文展示，但标为“相关记忆原文”，明确“相关不等于支持”“模拟模式不判断本题条件是否满足”；不再使用自动肯定式前缀，显式返回空 memory_citations/experience_citations。仍提取用户明确要求记住的候选，不影响确认/纠错/遗忘或用户记录。
2. CHAT_SYSTEM 明确召回是候选、ID 有效不等于支持；核对实体/时间/属性/范围，保留明确否定；缺失或冲突时不得肯定问题事实，不用相关来源支撑该结论；合法可答才回答引用。现有 8192 字节系统预留内的校验通过。

**这不是语义裁决器。** 提示词是行为约束，不能阻止脚本或未来模型忽略它。下面不受支持的注入仍被接受；没有在后端偷偷增加词法“蕴含”规则，没有实现或宣称运行时硬拒绝，也没有降低其风险级别。回答正确性/引用支持的独立评测仍缺，当前不能作为可信事实问答质量验收。

没有改变生产默认检索、词项/阈值、shadow 候选、旧评测、权限边界、费用闸或聊天历史。长期记忆遗忘后原聊天历史是否屏蔽仍待用户决定，不在本批选择。

## 真实 HTTP/Worker 合成探针

新增于已有 `tests/text_scenarios_e2e.py` 的独立回归方法，使用专用临时 H2、实际 API、领取上下文、Worker 和完成接口；同一实例串行执行，另列在报告 `additional_memory_support_boundary`，不混入冻结 30 题。

每例先经 mock 消息提取候选、用户确认，再开新会话查询；实际 SQL 候选须选中该私有记忆。检查默认 mock 的原文展示及空支持引用。随后另开会话，用明确的 `ScriptedOfflineModel` 注入断言，经实际 Worker 验证和完成接口，刻画 ID-only 边界。

| 旧暴露 strict_support 负例 | 3 | 3 | 3 | 3，均不受来源支持 |
