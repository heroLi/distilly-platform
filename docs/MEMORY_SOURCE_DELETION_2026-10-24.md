## 实际缺口与修复

合成用户在会话 A 产生并确认的记忆，可被同人物下的会话 B 检索。原实现删除 A 时删除了派生记忆，但只清理 A 自身的任务；已经领取该记忆的 B 仍能提交合法完成回执。修复前红测实际为 **HTTP 200 / 新增 assistant 1 条**，预期为 409 / 0。这是来源删除后的协议缺口，不是真实模型质量测量。

本轮沿用现有记忆失效策略：

- 删除会话实际移除派生记忆时，在同一事务取消同用户、同人物的所有排队/在途 CHAT。其他用户、其他人物及已完成任务不受取消影响。没有派生记忆的会话删除不会停止其他会话。
- 复用现有记忆服务的取消逻辑，清空任务上下文、结果、临时回复、租约及知识快照；不自动重发旧输入。
- 完成回执检查本轮选中的全部记忆 ID：必须仍为 CONFIRMED，原消息/原会话仍存在，记忆和来源均属于当前用户、当前人物。即使输出不填写记忆引用，也不能绕过检查。
- 来源会话删除、记忆修改/删除和 CHAT 完成按相同顺序先锁人物行，再处理会话、记忆行和任务。这样完成事务先提交则保留为历史；删除事务先提交则旧上下文不能继续完成。同一人物的这些短事务会串行，不代表验证了生产吞吐。

没有增加数据库迁移、依赖、外部索引或新的记忆架构；没有修改手机/PC 新视觉、现有静态页面、费用配置或真实出口。已完成的另一会话历史不会因删除 A 自动抹除，完成回执的历史幂等重放也不会新增回答。最终记忆检查验证的是存在、确认与来源归属，不是新增正文版本指纹或真实语义保证。
