## 新复现与最小修复

`PersonaTaskService.complete()` 对 `SUCCEEDED` 且租约匹配的请求，原先在当前权限复核前直接返回缓存结果。两个 Java 红测及真实 loopback HTTP 探针证实：完成后删除成员，或归档人物，重复完成仍返回 200 和缓存回答。助手消息数仍为 1，因此问题是越过访问边界返回缓存，不是重复写入。

修复只针对 CHAT 完成回调：按成员 → 人物 → 会话 → 任务顺序持短事务锁；先检查状态和租约，再对合法重放及首次完成均复核当前成员、人物可访问性及私有会话归属。撤权返回 403，人物归档返回 404，错误租约仍为 409。成员行锁使复核与返回缓存处于同一事务边界，顺序与现有领取／片段路径一致。

拒绝回放不会删除或重写已完成历史。权限恢复／人物恢复后，同一合法租约仍返回原消息 ID，消息数不增加，不重新生成模型输出。没有把历史回执改成当前来源的语义支持证明，也没有引入新的遗忘规则。
