`text_scenarios_v1.lock.json` 固定上述哈希与 30 项总数。入口先检查冻结完整性，再启动专用实例。以后扩充案例或调整期望须创建新版本、披露差异，不能删掉失败项。8 项轻量回归防止漏案例、重复案例、缺类别、单轮冒充多轮、未知动作静默跳过及 mock 质量打分。

样本全部为明确虚构的原创设定及合成 UTF-8 TXT。三类分别为 relationship、celebrity、colleague；celebrity 仍是原创虚构角色，不对应真实名人。每类完整覆盖以下十个结构情境：

| 类别 | 自动检查边界 |
| --- | --- |
| 安慰 | 两轮执行，短期情绪不作为已确认记忆 |
| 开心 | 两轮交流与状态连续性 |
| 冲突 | 含改身份/索要其他人记忆的输入；进入 Worker 的固定人格和私有记忆集合不变 |
| 追问 | 三轮近期用户消息连续性 |
| 未知事实 | 两轮无匹配记忆、知识和经历来源；不以 mock 套话判定真实拒答质量 |
| 资料纠错 | 待确认→确认→修改记忆；发布知识→负责人修订→再次读取当前来源，旧版本不改写 |
| 偏好 | 待确认不召回；确认后可召回；关闭/恢复记忆的上下文边界 |
| 删除/撤回 | 删除记忆和撤回知识时保留已领取旧上下文，尝试晚完成；检查取消和无新助手消息，再检查新上下文及删除会话 |
| 不同用户 | 私人会话/记忆拒绝访问；同空间显式选择的已发布知识可共享；阅读者不可读原文；跨空间不能绑定来源 |
| 人格升级 | 旧会话固定旧快照，新会话使用新批准版本，原版本保留 |

三类刻意重复相同十类结构，只有原创设定和数据不同，**不是 30 个独立语义发现**。这是公开工程验收集，没有保留集或泛化质量结论。既有词法开发/保留集及 9 个家族重叠披露继续保留。四组窄语义探针仍为 0/4；本轮不重定义、不重跑、不将它们计为通过。

## 实际执行方式

```sh
mvn -B -ntp -f server/pom.xml package
python3 tests/text_scenarios_test.py
python3 tests/text_scenarios_e2e.py
```

完整入口为 `python3 scripts/verify.py --e2e`，新增情境集是第 14 套 E2E。默认结果保存在忽略的 `server/target/text-scenarios-e2e/result.json`。

启动器先将工具链/区域变量白名单传给子进程，不读取 `.env` 或继承供应商、代理和真实数据库设置。每类使用独立临时文件 H2、拷贝的当前 JAR、动态回环端口和默认 JVM。通过真实 HTTP 提交、真实领取及上下文装配，随后同步调用现有 Python Worker 执行与完成逻辑；没有替代数据库、手工拼造上下文或后台调度吞吐验收。Model 固定 mock，网关调用方法被测试断言禁止。

每个情境使用独立工作空间。每轮检查当前消息、固定人格快照、精确记忆集合及来源标记、知识版本/原文/来源 ID、持久化消息对和情绪状态连续性。报告只保存案例、步骤、状态、来源数量与哈希；不保存材料/回答正文、令牌或临时绝对路径。API 日志仅留在忽略目录，不能随源码提交。

## 原始失败和最小修复

冻结集在旧基线首跑 **27/30**。三个 `*-08-deletion` 均在撤回已领取知识上下文后失败：预期 CANCELLED，实际 Worker 完成遭当前来源校验拒绝后转为 FAILED / INTERNAL_ERROR。首跑在该断言停止，后续删除步骤未执行，不能冒称那些步骤当时通过。新增 Java 定向回归先复现：撤回后任务仍为 RUNNING。

修复仅在撤回知识的既有事务内取消绑定该专题人物的排队/运行中 CHAT，清空任务上下文、旧知识快照、部分回应及租约。此策略与已有知识选择撤销一致，会保守取消绑定人物的活动聊天；不尝试从问题文本猜哪些聊天“可能不受影响”。未绑定人物、已结束任务及其他类型任务不受此更新影响。取消与来源撤回、原任务删除和审计一起提交；原有完成时来源校验仍保留。

定向回归检查运行中/排队任务、迟到完成被拒且无助手消息、未绑定人物不受影响，以及阅读者撤回失败后原任务和知识不变。该文件全部 13 项通过。未新增检索特例、改写提示词、调整预算闸或改变公开接口。

最终冻结集 **30/30 通过、0 失败**：96 轮已完成聊天、6 次已领取旧上下文的晚完成尝试。6 次均保持 CANCELLED，新增助手消息为 0。三次默认 JVM 启动为 3.700、4.044、3.156 秒；三个专用实例全部清理。初始 27/30 及 Java 失败复现单独保留，不能用最终通过覆盖。

新完整回归 `python3 scripts/verify.py --e2e` 通过：Java 234 项（新增 2 项）、Worker 86 项、冻结契约校验 8 项、启动器隔离 2 项、20 组 Node、16 个 JS 语法、架构边界及 14 套 E2E。新情境不是原生浏览器验收；既有浏览器测试按原范围重跑。负例中故意执行失效租约，现有 Worker 通用日志仍会输出 INTERNAL_ERROR 警告；本套检查服务端终态与消息数量，没有把警告隐藏或将其当作真正失败任务。对这类日志的细分尚未新增。

## 真实质量仍未测

五个维度为人物一致性、自然表达、情绪合理性、记忆正确性、来源可信性，各 1–5 分。均需独立人工查看真实输出；当前所有分数为 null、状态 NOT_MEASURED。平均至少 4 分和越权/删除后再使用为 0 次是路线图拟定目标，尚未达到或测得。

人工评审使用冻结 rubric 的统一分档：1 为严重/持续矛盾，2 为频繁且需修复，3 为表现混合且有实质缺陷，4 为一致恰当且仅有小缺陷，5 为各轮一致自然且依据可靠。逐案例、逐维度记录分数、对应轮次与理由；缺输出或未评维度留空，不能以 0 代替未测，也不能从 mock 自动填分。人物一致性检查固定身份与边界，自然表达检查重复套话和对追问的回应，情绪合理性检查触发与连续性，记忆正确性检查确认/纠错/删除/用户归属，来源可信性检查事实依据与未知时诚实程度。越权及删除来源再使用单独计事件数，不能用高平均分抵消。

mock 标记、情绪关键词、模板回答或来源结构命中都不能成为真实质量评分。删除记忆不等于删除旧会话历史；本套分别检查可召回的确认记忆、保留的短期消息及删除会话后的空历史，不把这三种含义混同。没有原生浏览器/视觉验收，也没有补上原生 BFCache 未命中的缺口；既有浏览器证据仍按原范围保留。没有生产 PostgreSQL、外部身份、负载、掉电/存储销毁或真实供应商验收。

下一关键路径是按冻结标准取得可独立评审的真实文字输出，而非给 mock 打质量分；真实调用条件未满足且收费已后置，保持未测。无密钥下可继续的完整工作是文字入口的能力状态与失败恢复一致性：基于服务端可证明的状态提示发布、绑定和 Worker 执行就绪，不从 API 环境猜供应商能力，也不扩展声音视频。
