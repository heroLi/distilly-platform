# 私人交流页面的浏览器返回缓存核验

本批事实基线为 `0822e6241fbe63a0a73c5d2d95fcd5a6dd93ee55`，独立分支
`resume/text-cost-gate-20261021`。仅原工作区、独立合成 H2 和 mock；真实模型调用为 0。

## 复现与修复

真实 Chromium 154 中打开合成私人交流和已确认记忆，导航至同源资料页，使用该页的退出按钮，随后浏览器后退。
页面实际经历 `pageshow(false) → pagehide(true) → pageshow(true)`，文档实例未改变，没有重新请求主文档。
修复前原页面仍持有旧令牌，会重新请求并显示退出前的私人回答；截图也显示了记忆输入框正文。
旧探针的 `memory_visible` 使用 `innerText`，不涵盖 textarea 的 value，不能将该字段的 false 解读为未显示记忆；后续探针改查实际 value。

问题在客户端恢复登录状态：离开时虽然清空聊天／记忆 DOM，内存中的登录令牌仍保留，恢复时直接使用它重新读取。
这不是服务器新 HTTP 请求跳过权限检查的问题。隔离测试库撤销成员资格后，恢复页面没有显示聊天或记忆正文，但截图复核发现会话下拉框仍显示私人标题。
因此进一步补上私人页面显示门禁：离开有私人会话的页面时隐藏旧工作区；返回后会话和记忆均重新读取成功才显示，当前访问失效或读取失败则被动清理并显示登录页。
这保留保持授权时的正常恢复及未发送草稿，防止仅清正文却留下标题等旧页面内容；不改服务器历史记录。

修复让真实持久页面恢复在任何旧身份读取和轮询启动之前，先核对同一标签页共享的登录状态。
已退出、身份已替换或共享存储不可读时，立即失效旧读取、清空私人交流／记忆／草稿并返回登录页。
此清理不删除其他页面刚完成的新登录，也不删除 SQL 中的历史交流。
续审发现被动清理原先也会删除整个共享发送回执表：真实 BFCache 切换账号场景和使用真实发送控制器的单元红测均已复现。
修复为被动失效仅 reset 旧控制器的内存状态，保留新身份已持久化的请求标识／摘要；主动退出仍执行原 clear 规则。
保持同一身份时保留原有授权读取和恢复路径，服务器继续复核当前权限与来源。
现有主动退出复用同一清理函数；前端资源版本已递增。

## 浏览器测试条件

Playwright 默认带有 `--disable-back-forward-cache`，现有 route 拦截测试不能作为真实 BFCache 的验收证据。
新增共享启动器的明确选项 `native_bfcache=True`：使用完整的新 headless Chromium，仅忽略这个禁用 BFCache 的测试默认参数。
没有禁用缓存，没有 CDP 缓存开关，没有请求拦截，没有伪造 pageshow，也没有放宽产品安全策略。
普通测试的默认启动方式不变。CI 原有固定 Playwright 和 Chromium 安装步骤已提供所需浏览器。

可复用回归：`python3 tests/bfcache_return_e2e.py`。
脚本使用临时文件 H2、loopback、默认 JVM 和原 30 秒启动门槛，合成 mock 完成发布、交流及记忆确认。
授权恢复、离开期间纠错、人物归档失权、在资料页退出、在资料页切换账号五组都必须实际命中 BFCache；未命中会报失败，不会当成通过。
测试被接入 `python3 scripts/verify.py --e2e`。退出后的普通网络刷新另行记录。
