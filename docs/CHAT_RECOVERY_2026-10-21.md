# 当前聊天的中断、停止与显式重试

本轮在原工作区、`resume/text-cost-gate-20261021` 分支的 `9cf68c9e5272053e6f44264f121ec74dd913bd17` 干净基线续做，无并发编辑。用户将模型收费后置；本轮未改费用安全闸，真实模型调用为 0。

## 原生浏览器复现与改动

旧版本的聊天失败后，聊天页状态为空，停止/重试只存在于隐藏的人物工作室任务记录；用户不能在当前聊天中判断发生了什么或直接恢复。基线截图与结果独立保存在 `data/resume-20261021/chat-recovery/baseline2/`，没有用新页面冒充旧行为。

现在聊天页直接显示当前回应的排队、进行中、失败和已停止状态，提供“停止本次回应”“重试本次回应”和只读“刷新回应状态”。原任务记录继续保留。重试复用原任务和原用户消息，不再次发送输入框内容；输入框草稿保留。停止后的部分流内容被移除，不冒充已完成回答，也不提供取消任务的重试入口。

停止/重试复用既有服务端接口和权限规则。重复点击被当前操作锁阻止；操作响应丢失或后续状态读取失败时，页面要求先 GET 核对，不自动重新 POST。刷新失败可显式再次读取；401/403/404 清空当前聊天/记忆并禁用操作。人物、会话、选择序号、页面生命周期均限定响应归属，旧成功或旧失败不能写回新会话。

会话只读结果新增可空的 `latest_chat_job`，字段限于 `id/status/error_code/attempt`；在既有会话归属和空间授权检查后读取。查询按当前会话隔离，独立于人物任务列表的 100 条上限，采用 created_at DESC、id 的既有稳定顺序。当前 active job 优先显示。没有新写接口、数据库迁移、供应商调用或费用逻辑。

页面离开时增加 epoch、清理聊天/记忆、失效旧请求并停止轮询；缓存页面恢复时先重新读取会话，再恢复周期读取。普通刷新与浏览器前进/返回也从服务端读取持久状态。退出清空聊天、记忆、文本草稿与图片选择。此处不在浏览器本地保存聊天正文或草稿。

## 新验证

- `ChatRecoveryStateTest` 四项：失败/重试不重复输入；取消后晚完成被拒绝；私人会话和实际撤销空间成员权限拒绝；其他会话超过任务列表上限仍能返回当前状态。
- `chat_recovery_ui_test.cjs` 26 场景：六种状态、重复点击、停止/重试丢失响应、GET 核对、401/403/404、会话/选择序号/epoch/页面离开/重置后的晚成功和晚错误、状态错配、读取失败恢复、终态变化轮询及缓存恢复定时器。
- `chat_recovery_e2e.py` 原生 Chromium 六组：当前失败可见与显式重试；丢失已提交响应后只读核对；双击停止只发一次请求、临时回答消失、原租约晚完成 409；停止后通过实际 mock Worker 完成新交流；刷新与原生离开/返回；旧会话晚 403 不污染新交流；实际归档后的 404 清理与退出。正文全部合成，浏览器不访问外部地址。

缓存恢复分支有实际函数回归；原生导航测试将 `pageshow.persisted` 实测值另记在结果 JSON，只有值为 true 时才能称本次实际使用了 BFCache。不能用事件单测冒称浏览器缓存分支已实测。

最终完整回归通过：Java 214 项、Worker 86 项、17 组 Node、14 个 JS 语法检查、启动器隔离 2 项、架构检查和 10 套 HTTP/浏览器 E2E。最终聊天浏览器六组通过，异常/外部请求均 0；默认 JVM 启动 5.571 秒，测试进程已清理。原生返回的 `pageshow.persisted=[false]`，因此实际缓存命中分支仍仅有函数回归，不能称原生 BFCache 命中已验收。Java 17.0.20.1 / Python 3.12.14 / Node 24.19.0 为本工作区实测，CI Python 3.11 / Node 22 未在此运行。

完整入口为 `python3 scripts/verify.py --e2e`，含新聊天恢复 E2E。原人格绑定旅程、记录卡纠错、筛选、费用安全闸与执行预算都保持回归。新测试编写时的 Worker 请求头 401 和测试间未清理排队任务导致的夹具错误已分别修正并保留原失败日志；它们不是产品缺陷复现。

## 演示与边界

```sh
mvn -B -ntp -f server/pom.xml package
python3 scripts/run_synthetic_demo.py --port 18080
python3 tests/chat_recovery_e2e.py
```

本机打开 `http://127.0.0.1:18080/`，用公开演示令牌 `demo-owner` 创建、发布合成人物并新建交流。排队/回应时可在聊天中停止。mock 通常很快成功；自动化脚本使用合成 Worker 失败回调和流片段，稳定展示失败、重试和停止，不需破坏真实模型配置。测试结束清理 API/Worker，不留下公网或常驻预览。

这不是完整消息提交幂等：本轮没有为原始消息 POST 增加请求标识或跨刷新草稿保存；提交响应丢失时不能据此承诺重复发送原消息安全。取消的服务端租约保护已复用，未新增真实供应商中止能力。缓存恢复、桌面 Chromium 与 mock 流程不代表所有设备或真实模型质量通过。

四组窄语义探针仍 0/4，旧 247 项候选未恢复。文字质量、语义召回、生产身份/PostgreSQL/备份和真实模型仍有独立验收边界。后续无密钥事项应先复现原始消息提交结果不明时的交互缺口，再决定最小请求幂等契约；不要把该问题混入任务重试或重开计费审计。
