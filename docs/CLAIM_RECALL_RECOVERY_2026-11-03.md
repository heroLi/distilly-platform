# 领取中断、接管与撤权片段回调（2026-11-03）

## 新执行的隔离验证

从 `c9d4b635d37552f205982b10e53365fcd7f7d7e0` 出发，复用原云环境的现有工具和类路径，使用专用临时文件 H2、loopback Spring 服务、真实 `worker/worker.py` 的 mock 模式。测试专用 provider 委托原 SQL provider，取得真实引用后用 latch 暂停；未写入产品配置、安装服务或调用真实模型。

5 组新实验覆盖：

1. 实际 Python Worker A 在服务端召回暂停时被 SIGKILL；注入租约过期后，实际 Worker B 接管并只完成一次。未过期时其他领取返回 204；重复完成稳定；存活服务的旧领取请求最终返回 204。
2. 接管后纠错取消旧任务，旧完成拒绝；新任务使用纠正后的当前 SQL 正文并只完成一次。
3. 接管后撤销成员权限，完成被拒绝、私有会话读取被拒绝、后续领取没有私有 payload；其他合法用户的独立会话可继续，不能召回原用户记忆。
4. 接管期间删除来源会话，旧结果不恢复；新合法任务使用空记忆集合。
5. 召回暂停时实际 Spring 进程被 SIGKILL；同文件 H2 重启后保留已提交 RUNNING 租约，未过期不可抢占，注入过期后实际 Worker B 完成一次，旧租约回放拒绝。

每组强杀一个实际 Worker A，另强杀一次专用服务进程。旧租约完成、片段、释放、续租、失败 5 类回调通过服务代理显式回放；不是声称被终止的进程自行发送了回调。租约到期通过仅作用于测试任务的 `lease_until=0` 注入，未等待自然 300 秒。默认 JVM 与 30 秒启动门槛不变。

## 确认的缺口与最小修复

初轮以上 5 组通过后，追加检查发现：接管方持当前有效租约，但其成员权限已撤销时，完成返回 403，流式 `delta` 却仍返回 200 并写入 `partial_reply`。这不能由“最终未完成”推断为“没有陈旧写入”。合法字段 `partial` 的原生 HTTP 探针与两项 Java 失败回归确认了问题。一次使用错误字段的探针返回 422，已保留且不计为产品失败证据。

修复仅收紧片段回调：短事务按成员 → 人物 → 任务顺序锁定，再检查当前 CHAT／RUNNING 状态、租约与到期、当前成员和私有会话访问权。旧租约先返回 409，不能取消接管方租约。当前租约失权时，取消该任务并清除片段与 payload；取消事务提交后才返回 403／404，避免异常回滚清理。合法片段和完成协议保持原样。

记忆纠错、遗忘和来源会话删除的现有服务会先持人物锁并原子取消相关任务；片段写入使用同一人物锁及当前任务状态，防止跨过这些取消。未增加自由回答语义判定，也未修改默认召回、冻结源码或旧评测。

新增 3 项 Java 回归覆盖撤权清空已有片段、旧租约不能清理替代租约，以及纠错后的新任务可以继续流式写入并幂等完成。故障实验在修复后再次执行；最终统一入口与精确 CI 结果见本批验收记录。

## 验证边界

这是专用合成 H2 的确定性故障注入与实际进程终止，不是生产 PostgreSQL 压测或真实 Hindsight／模型验收。已发送给当时合法 Worker 的内容无法追溯收回；撤权后用户读取仍须通过现有鉴权。清空在失权片段回调被处理时发生，不声称直接修改成员数据库后会自动清理所有静止任务。

片段写入增加了短事务权限复核，未测生产高并发流式延迟。原只读召回事务仍占用连接；历史间歇启动尾延迟不因本批一次通过而称已解决。真实模型调用 0，原语义 0/4、中文 12/21、旧 247 项未恢复的边界不变。原规划草案与恢复证据保留。
