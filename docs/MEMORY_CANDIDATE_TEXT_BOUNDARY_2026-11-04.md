## 确定性缺陷与最小修复

Python 旧 mock 的 `message[:300]` 按 Unicode 码点切片，含 supplementary Unicode（例如 emoji）时可能超过 Java 的 300 个 UTF-16 单元。两个合法正文控制分别生成 301、324 单元引文；Java 因 `invalid_text` 拒绝完成。独立实际 HTTP/mock 红测确认任务 FAILED，而预期为 SUCCEEDED。

只修改 `worker/persona.py` 的长度兼容：

- mock 来源引文逐字符累积 UTF-16 宽度，不超过既有 300 单元；不拆 Unicode 字符，不改完整候选 body，不补写或省略否定/条件/时间。
- Worker 对生成结果的引文长度验证使用相同 UTF-16 单元计数；来源子串核验不变。没有裁剪真实生成结果，也没有真实模型验证。
- Java、正文上限、待确认/可编辑性、来源和权限合同均不改。超过 1000 单元正文仍拒绝，未用自动截短来“修复”长消息；其交互改进不在本批。

这是引文长度的跨运行时兼容修复，不是语义提取、支持判定或独立盲测能力提升。
