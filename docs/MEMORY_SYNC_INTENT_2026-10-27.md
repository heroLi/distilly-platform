## 最小实现

追加 `V012__memory_sync_intents.sql`，不修改旧迁移。新增一个 Provider 中立的本地 outbox 表，记录人物/用户/记忆范围、项目、递增修订、持久 UUID、RETAIN/DELETE 目标、状态、来源指纹、当前待处理正文及时间。它不外键依赖会被删除的记忆/消息，便于保留无正文的清理意图。没有另建 Worker、租约调度器、HTTP 入口或供应商配置。

确认/纠错/拒绝、遗忘，以及删除来源会话之前，在原事务和现有人物锁内记录意图：

- 仅合法当前已确认来源形成 RETAIN；不导出 PENDING 或不合法来源。
- 拒绝、遗忘、来源删除形成 DELETE；相同目标重复保存沿用原修订和 operation_id，不创造新消费操作。
- A→B→A 产生三个不同操作及递增修订；不会因 A 的正文指纹相同而复用第一次的操作 ID。
- 新目标提交时，旧未派发项变为 SUPERSEDED；旧正文快照立即清空。已经交付给 fixture 或结果未知的旧项保留为顺序阻挡，不能假定没有执行。
- SQL 修改、取消旧聊天和意图写入同事务提交或回滚；日志失败不能悄悄丢掉同步意图却宣布记忆已更新。

版本含义分开：页面 expected_revision 仍是编辑冲突指纹；Provider SourceRef 仍是当前来源/正文指纹；新增 outbox revision 是本范围内目标变化的持久顺序号，不冒充真实供应商的索引版本或账单编号。

## 顺序、未知结果和权限

| 本地状态 | 本批含义 |
|---|---|
| PENDING | 目标已提交，尚未交给离线 fixture |
| DISPATCHED | 已交给 fixture，可能出现未知结果；不证明发出了真实请求 |
| UNKNOWN | 需要核对，重启或时间流逝不会自动解除 |
| ACKED | fixture 提供了已终结标记，不代表供应商真实成功或删除证明 |
| SUPERSEDED | 未派发的旧目标被替代，不再派发 |

`stageFixture` 仅交付当前 PENDING 目标，并重新核对当前 SQL 状态/来源。只要同一记忆存在 DISPATCHED/UNKNOWN 项，后续纠错或删除立即返回明确冲突，不盲目重发或跨过它。并发交付只成功一次。日志独立于 persona_job，不把本地未决同步当成一个阻塞聊天的模型任务。

fixture 核对旧操作已终结后，只更新该操作；若已有更新修订，回执标记 current=false，不能将已遗忘记忆写回 SQL、覆盖新目标或给新修订冒领回执。错误修订、未证实终结、未派发回执被拒；重复终结不再修改状态。接下来可以交付已持久保存的最新删除操作，仍沿用原 UUID。

所有操作由当前人物所属项目和当前用户授权，负责人不能查看或控制他人私人意图，撤权后拒绝访问。读取摘要不返回正文、来源内容或凭据。接口都是 Java 内部方法，没有客户端 bank 或 Provider 控制入口。
