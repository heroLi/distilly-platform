# 任务领取与记忆召回的事务边界（2026-11-03）

## 确认的问题

基线 `d0fcd844426e1030ada4a25890140af6010ccc4e` 的 `PersonaTaskService.claim()` 在同一事务中锁定人物、写租约、调用召回并组装上下文。记忆纠错、遗忘、来源会话删除也需要人物锁，因此较慢的召回会占住这些操作的锁，并让同人物其他会话被 `SKIP LOCKED` 跳过。

独立合成 H2 的两项失败回归已复现：先取得真实 SQL 候选，再用 latch 暂停返回；另一连接的 `FOR UPDATE NOWAIT` 立即返回 H2 `50200`（0 ms 等待），而另一会话领取返回空。不是用运行耗时推断阻塞，也没有提高锁超时、启动期限或 JVM 性能选项。

## 最小改动

1. **短事务预留**：保留原人物互斥、访问检查和条件租约更新，提交 RUNNING 租约后释放锁。
2. **领取事务外召回**：复用原有只读召回事务和默认 SQL provider；不持有预留阶段的人物／任务写锁。原只读事务仍占用数据库连接，不能声称没有任何事务。未接外部模型或 Hindsight。
3. **短事务输出复核**：按成员 → 人物 → 会话 → 任务顺序锁定，检查当前成员权限、会话所属、固定人格版本、当前租约及到期状态，重新从 SQL 解析当前确认的记忆来源及内容指纹，再按原上下文预算组装输出。不存在、已取消、旧租约、失权或版本变化的请求不会返回旧上下文。已变更的来源指纹被过滤；正常记忆变更流程仍取消旧任务。

`MemoryRetrieval` 与其冻结摘要完整保留；词法排名、阈值、数量、预算和默认 provider 均未修改。领取器在输出短事务中追加 SQL 来源／正文指纹核对。原文参考 API 与页面不变，不涉及聊天历史的遗忘产品语义。

预留租约现会在选择期间可见，其他领取者不能重复取得同一任务。普通异常按原租约条件释放预留，不重置其他领取者的租约；进程终止仍依赖现有租约到期／最大尝试机制恢复。没有延长租约、调低正式断言或引入新的服务。

## 回归与验收口径

新增 `ClaimRecallIsolationTest` 的 13 项合成检查：

- 遗忘能在暂停召回期间立即取得人物锁，旧任务不返回 payload；同人物另一会话可继续领取。
- 撤权、纠错、来源会话删除和人格版本变化后旧结果不返回；纠错后的新任务读取当前正文。
- 旧租约结果不清理替代租约；合成到期状态可恢复；异常释放不消耗这次未交付的尝试。
- 召回复用原只读事务但不占领取写锁，独立 SQL 指纹复核拒绝旧版本；最终 SQL 解析确实在事务中持有成员和人物锁（独立连接 NOWAIT 验证）。
- 同一任务在召回等待期间不重复发租约；关闭记忆时不调用 provider。

首次全套因本批拆分触发旧 shadow 评测的冻结源摘要检查而停止；失败证据保留。未更新旧锁或旧评测，改为保留完整原召回实现的方案。先跑相关 Persona、MemoryProvider、MemoryProvenance、MemoryReference、shadow 冻结检查和新增并发回归，再串行执行 `python3 scripts/verify.py --e2e`。最终候选及精确提交 CI 的实际结果另有验收记录，旧结果不能代替本批结果。

## 真实边界

验证环境是隔离合成 H2 与现有 mock，不是生产 PostgreSQL 压测，也未新增“在暂停选择期间强杀独立服务进程”的验收；租约恢复用确定性过期状态检查，完整套件另保留已有进程终止／重启回归。

事务拆分不保证 SQL 扫描没有连接、CPU 或 I/O 成本，不为未来真实 provider 增加无限等待许可；外部服务的超时、取消、费用与数据授权仍须独立验证。最终复核是输出前的事务边界，已发送的数据不能追溯收回。
