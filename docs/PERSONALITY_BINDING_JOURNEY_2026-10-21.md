## 实际缺口与改动

路线图已有“创建到绑定串联”待办。现有“沿用人物设定新增人格”已经实现，且不会复制材料授权勾选，本轮保留。原生浏览器在旧 JAR 上复现：从人物 B 进入人格库，绑定框默认选择列表第一位的另一个人物 A；绑定成功也没有返回 B 开始交流的入口。

现在，绑定框仅在来源 UUID 属于当前授权人物列表时预选来源人物；没有有效来源时要求显式选择，不默认第一位。确认仍需用户点击。成功后提供“返回该人物开始交流”，只携带当前空间和人物 UUID，不携带正文或令牌。工作室仅在当前已授权空间内使用返回目标，不通过 URL 自动切换空间；目标缺失/归档时清空旧人物和聊天，提示重新选择，不回退到其他人物。正常刷新已选人物优先于 URL。

绑定响应丢失时，选择保留，并提示先用“核对绑定状态”读取现状。该按钮只 GET，不自动重发 PUT。只有当前发布的 APPROVED 版本明确包含相同人格和版本绑定时才展示成功。401/403/404 禁止继续操作；关闭窗口、退出或切空间后的晚响应不得更新页面。已确认成功但列表刷新失败时仍保留成功事实与返回入口。

服务端保持原权限、空间、素材、版本和生成中检查及锁顺序。当前已发布快照的源人格、源版本和目标定义全部相同时，同绑定重复/并发提交返回现有快照，不追加版本或审计。目标定义或源版本变化仍产生新快照，旧交流继续固定旧版本。此处是 PUT 当前绑定的幂等，不是通用请求账本；不同绑定按显式操作顺序生效。

## 本机合成演示

```sh
mvn -B -ntp -f server/pom.xml package
python3 scripts/run_synthetic_demo.py --port 18080
```

打开 `http://127.0.0.1:18080/`，使用公开演示令牌 `demo-owner`。创建原创合成人物，点“去人格库创建”，上传合成 TXT，点击显式沿用设定，确认授权后生成/审核/绑定，点击返回人物开始交流。工作资料纠错入口仍在聊天页“先核对资料记录”。启动器固定 mock、回环地址和独立文件 H2，不读取 `.env`；停止后不保留服务。没有公网部署或常驻预览，不保证工作区销毁后的数据库持久性。
