# SUP-001：事实支持与窄可答合同的离线设计

日期：2026-11-11。状态：**DESIGNED_NOT_IMPLEMENTED**。源码基线：`70f20db0da0dfd91ed49682472b9cf0fd82af93f`。这是设计交付，不是运行时支持判定器、默认聊天协议变更、语义验收或上线批准。

机器可读设计清单：[memory_support_reference_v1.design.json](contracts/memory_support_reference_v1.design.json)。该文件只供设计一致性检查，没有运行时加载器。对应 [SUP-001 backlog](PROJECT_BACKLOG_2026-10-15.md)；代码和原有评测集均不修改。

## 为什么现在可以做

SUP-001已有明确边界：比较结构化支持声明、保守拒答及显式原文参考，覆盖条件缺失、明确否定和合法可答控制，不把ID或关键词当蕴含证明。设计只需当前源码、已暴露合成边界和兼容性约束，不依赖Colab实际运行、外部LLM、模型安装、CI读取或独立封存集。

本轮没有执行模型或应用测试。Colab合成包已准备不等于资源、下载、模型或质量已验证；本设计不触发上传、账户、持久访问或新费用。Actions及官方源/许可拒绝没有因此解除，不重试或换路绕过。

## 现状：保证的与未保证的

| 路径 | 当前可核合同 | 不能据此确认 |
|---|---|---|
| 默认CHAT | Worker校验引用ID属于本轮输入；Java复核actor、任务、租约、权限及引用集合，保存字符串answer | 不校验answer逐项受支持；空引用也不是答案未使用私人事实的证明 |
| CHAT增量 | delta检查当前租约、成员/人物/会话权限和长度 | 增量文本没有语义支持判定；不能等完成后才校验并声称此前断言未曝光 |
| 原文参考 | SQL-only、本人当前CONFIRMED记录、来源及指纹复核、显式NOT_ASSESSED，无CHAT任务/模型/delta | 不是当前问题的事实答案，不是原聊天全文，也不证明记录本身真实 |
| 既有失败探针 | 5/5不受支持的离线脚本断言可通过ID-only链路 | 这是已知未解决边界，不是本轮新复现或质量通过 |

用户确认、source ID有效、quote为子串、词面相关、向量/重排分数、提示词要求或模型自报supported均不是语义支持证明。合法可答的来源也不能让一个未验证的自由改写自动变成受支持答案。

## 三种方案的判定

| 方案 | 能机械保证什么 | 缺口/决定 |
|---|---|---|
| A：复用已有显式原文参考 | 服务端读取获准SQL正文、字段白名单和安全显示；不混入模型自由断言 | 最小可用参考切片已经存在，不另造平行API/页面；仍标NOT_ASSESSED |
| B：结构化声明＋引用/引文 | 可检查schema、ID/来源/版本身份、引文定位或是否缺字段 | 即使声明结构完整、引文逐字匹配，也不能判断条件、否定或时间蕴含；仅加supported=true无效 |
| C：受支持的事实回答＋保守拒答 | 需要经过验证的逐断言判定或更窄的确定性可答规则，失败时不发布事实断言 | 当前没有这种判定器；不伪造VERIFIED，不用模型自评替代独立验证 |

**本设计建议冻结的最小边界是A，而非把B冒充C。** 保留现有参考入口作为明确选择的非事实判定路径；默认CHAT保持现状。若未来要将窄合同接入聊天，必须先确认opt-in版本、旧客户端兼容及发布隔离，再实施。这里不自动改变默认体验或宣布自由回答缺口已闭环。

## 直接复用的现行合同，保持不变

现有请求是 `POST /api/personas/{id}/memory-references`，JSON仅有 `mode=SOURCE_REFERENCE` 和 `query`，query上限4000。其它字段/模式按当前实现拒绝，不接受客户端bank、actor或供应商URL。Controller保持`Cache-Control: no-store`。

现有响应字段为 `contract=MEMORY_REFERENCE_V1`、`mode=SOURCE_REFERENCE`、`support_status=NOT_ASSESSED`、`notice`、`references`。每项仅含`memory_id`、`source_message_id`、`record_text`、`record_fingerprint`、`quote_kind=CONFIRMED_MEMORY_RECORD`，最多12项。

`record_text`是SQL已确认记忆记录正文，可能经过用户纠错，**不是原始聊天消息逐字副本**。`source_message_id`用于既有独立鉴权来源回查，不能因此扩大读取历史范围。记录和原始来源界面已有区分说明，不新造监护角色或默认公开数据。

## 权限、来源、版本与线性化

1. 参考读取沿用成员→人物的锁序和事务授权快照，在该快照中选取本人CONFIRMED且有效来源，核指纹，再返回SQL记录正文。不得将外部bank或模型字段当认证。
2. 参考接口已有快照合同不变。写入在快照之前完成，可读当前新记录；记录在选择后出现指纹/归属冲突则沿现有拒绝路径。快照检查点之后才发生撤权/修改，本次获准快照可能完成，后续请求用新状态。不承诺HTTP序列化/发送时的零窗口。
3. 默认CHAT的当前领取、租约、固定会话版本、取消/失权屏障继续独立生效；如果未来新模式借用任务通道，必须在发布前复用这些检查。不能只用内容指纹判断A-B-A；旧任务被取消/租约失效后，即使正文回到旧值也不能复活。
4. `record_fingerprint`是内容/来源当前指纹，不等于同步日志单调revision或供应商ACK。设计不新增跨模块generation字段，也不声称现有读取有未实现的全局线性化保证。
5. 本轮不把普通读取的最终SQL复核规则强加给原文参考，也不反向增加网络IO期间的数据库锁。

## 发布边界：防止“先流出、后说已校验”

现有参考API没有模型和delta通道，应继续直接复用。新窄模式若将来进入CHAT，服务端必须在领取前固定模式及兼容版本；不能等Worker完成后才据其自报字段选择安全模式。

在尚无事实支持判定器的参考边界中：

- 可显示固定状态说明和经SQL核验的记录原文；不显示模型自由answer、情绪理由中的事实断言或未经核验的历史回答。
- 不将原始模型token以delta先写入私人消息/轮询响应。已经发送字节不能靠随后清空界面或失败回执撤回；默认CHAT当前行为不能被重新命名为具有此保证。
- 若未来额外传输有预算，只可整条省略并明确缺省，不能截断同一记录尾部的条件/否定后再当完整记录。现有参考API字段和预算行为不因这条未来规则改变。
- 无匹配是“未找到可展示的相关记录”，不是“事情从未发生”；来源/权限失败不能改走别人的bank或让自由模型补答。
- 失败、取消、过期或未知结果保留既有恢复/费用边界，不新增自动外部重试或用新LLM填补支持缺口。

这是一份拟议发布约束，不是本轮实现。没有增加API参数、模型开关、消息类型、数据库字段或新UI。

## 冻结的设计场景清单

以下是已暴露问题/源码边界的设计要求清单，不含新的测试问答或gold，不是封存集、语义分类器或运行结果。机器JSON有14项；本轮只检查覆盖和自洽。

| ID | 场景 | 设计要求 |
|---|---|---|
| D01 | 来源缺少问题条件，附有效ID的自由断言 | 不提升为已支持事实；可显式展示获准原文并保留NOT_ASSESSED |
| D02 | 来源明确否定，模型却作肯定断言 | 同上；不能用引用存在覆盖否定 |
| D03 | 来源合法可答，但输出是自由改写 | 当前无判定器仍不得自动标VERIFIED；默认CHAT不在本轮改动 |
| D04 | 本人合法、当前、完整记忆记录的参考展示 | 正向路径保留，展示记录原文、NOT_ASSESSED和区分说明 |
| D05 | 当前没有匹配来源 | 保留空参考状态，不推断事实不存在，不跨scope填充 |
| D06 | 请求注入actor/bank或越权选择资料 | 沿当前请求/权限拒绝，不泄露私人正文 |
| D07 | 已选引用与SQL当前指纹不一致 | 不发布旧记录，遵循当前changed错误合同 |
| D08 | 撤权/修改发生在参考授权快照之后 | 不宣称可撤回既有快照；后续新请求必须用新状态 |
| D09 | 旧Worker在取消或租约过期后晚到，正文A-B-A | 不能仅凭相同正文指纹重新发布旧任务 |
| D10 | 未验证断言先通过流式片段到达 | 参考路径不接原始CHAT增量；未来新模式需先隔离发布 |
| D11 | 模型自报supported或引用/引文都合法 | 仍不足以生成VERIFIED或事实支持结论 |
| D12 | 未来额外传输预算不足以容纳整条记录 | 整条省略/说明，不能削去尾部条件再当完整记录 |
| D13 | 记忆正文含HTML/指令样式文本 | 只作为文本显示，不执行或改变scope/系统规则 |
| D14 | 自由断言没有任何citation | 空引用不能作为已支持、无私人依赖或安全事实的证明 |

## 进入实现前的门槛

本设计完成不等于这些门槛已满足：

1. 评审明确选择继续仅复用已有参考入口，还是另行实现显式opt-in聊天合同；不默默迁移默认CHAT。
2. 若选择新合同，先冻结协议版本、旧请求/响应兼容、服务端模式绑定、输出持久化/增量隔离以及失败/重试语义，再写真实红绿回归。合法路径必须保留，不能为了安全演示一律破坏默认回答。
3. 若要宣称支持事实回答，还需真正的可答定义和独立验证，涵盖缺失条件、否定、实体/时间/范围混淆、无答案与合法回答；结构校验或相似度分数不替代。质量/语义门槛需执行前明确，不能照抄未审草案阈值。
4. 实现时覆盖失权、来源/版本变化、A-B-A/租约、重复回调、刷新/晚响应、安全显示及发布边界；按风险跑默认Java/Worker/前端/E2E。不能以本文或清单通过代替这些回归。
5. 不依赖Colab准备包即称模型通过；真实模型、费用、数据、独立封存和CI访问条件分别处理。既有拒绝不重试。
