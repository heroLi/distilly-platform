# 多页私人交流失权后的界面清理

事实基线：`e8e9abc7b8f0a0f7a0e39c58528fe168acc14658`，分支 `resume/text-cost-gate-20261021`。
本轮延续 M0 私人记忆／交流安全边界，不接入 M1 外部模型，不改变检索、遗忘或费用规则。
已有规划草案保留未提交；四份指定 10/15 原路线／基线／backlog MD／CSV 仍缺失，不补造历史验收。

## 实际核查与红测

当前 `PlatformSession` 使用同源、按标签页隔离的 `sessionStorage`。两个模块在同一标签页共享登录，另一标签页退出不会注销此页，普通网络重载仍可按此页有效身份进入。
这符合现有存储契约，不是已实现全浏览器退出；本批不新增全局注销或广播机制。

原工作区独立合成 H2 夹具中，真实 Chromium 打开私人聊天和记忆，再用 `window.open` 打开同源资料页。
资料页退出及另一个有效账号登录都未破坏原页的合法独立登录。
随后测试夹具仅删除合成数据库中该用户的成员资格，原页真实轮询已收到 403，回答正文被清空，但私人会话标题和未发送草稿仍可见。
执行 `bring_to_front` 后残留仍在；普通网络重载后则消失。未拦截网络或伪造权限响应。
这是当前拒绝响应处理的遗漏，不是服务器新请求绕过权限，也不是 BFCache 恢复失败。

`data/resume-20261103/multi-tab-access/native-red-result.json`、`native-red-after-denial.png` 和 `native-red.log` 保存原始红测。
`unit-red.log` 在基线源码上确认当前拒绝回调未清理会话标题；测试夹具最初缺少错误标签依赖的异常日志另行保留，不将该夹具异常称为产品红测。

## 最小修复

现有聊天拒绝回调改用统一私人会话清理：失效在途读取，递增会话 nonce，清空会话选择项、回答、记忆、未发送文字和图片，关闭并清空记忆来源／原文参考／同步状态窗口，再渲染不可访问状态。
保留账号、空间和人物上下文，保留按标签页登录和发送回执；不写服务器历史、不重发任务、不取消其他身份的操作。
原有 epoch／nonce 检查继续拒绝旧响应，所以旧会话晚到的 403 不会清理新会话或新草稿。
人物访问恢复后可通过现有刷新入口重新载入原历史，不需重新登录或增加消息。
前端资源版本递增；没有新页面、接口、依赖或权限。

## 不能混称的边界

本机完整 headless Chromium 154 在两页执行 `bring_to_front` 后，二者的 `visibilityState` 和 `hasFocus` 均报告 visible／true。
因此本轮证明的是实际多页交互、已处理当前拒绝响应后的清理和普通重载；没有证明真实后台隐藏、冻结、节流或切回前台前的显示行为。
未伪造 visibilitychange、未用 CDP 假状态代替原生行为，也未安装显示服务器或改浏览器安全策略。
真实后台验收仍需能实际产生 hidden→visible 的受控浏览器／显示环境；没有该条件时保持未验。
全局退出、跨浏览器会话撤销也未实现或验收，不能用本轮测试声称已有。

所有资料合成，真实模型调用 0。语义 0/4、中文 12/21、旧 247 项未恢复及历史间歇启动尾延迟仍保持原事实。
