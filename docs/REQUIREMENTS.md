## 产品目标与边界

让用户创建有稳定人格、自然情感表达和持续记忆的虚拟人，并逐步赋予声音和视觉形象，最终完成创建、调试、发布和接入闭环。
同级 distilly-platform-jd 承担团队共享工作知识库与工作 Skill；本项目以虚拟人及其互动体验为核心。
人物可由用户原创设定，或基于明确授权材料生成。材料事实、用户设定、模型推断分别记录，推断不得伪装为真实经历或来源事实。

## 第一阶段：文字人格、情感与记忆

- 人物创建：名称、背景、性格、价值观、表达习惯、兴趣及互动边界；支持手工设定与材料辅助生成，生成结果可编辑和预览。
- 人格版本：草稿、审核、发布、历史版本与回滚；每段对话固定人格版本，升级由用户明确选择。
- 连续交流：多轮上下文、流式回答、失败重试；人物保持表达与行为一致，知识不足时保留不确定性。
- 情感表达：根据当前交流、人物特点和关系上下文调整情绪、语气与回应；情绪具有强度和变化过程，可在调试中查看依据，不能仅靠固定语气词表现。
- 关系与记忆：区分短期上下文、人物背景与用户共同经历；长期记忆记录来源、时间和所属用户，支持确认、查看、纠正、删除与关闭。
- 工作知识可以成为人物的可选能力，不作为人物模型和情感机制的替代。

## 后续阶段

第二阶段接入语音识别与合成，支持音色配置、语气、流式播放与打断；明确声音使用授权。第三阶段加入形象生成、图像输入以及表情、口型和动作联动。第四阶段提供人物模板、创建向导、预览调试、发布管理、调用接口与运行管理。
浏览器语音、模型TTS/ASR、图片交流、形象上传与生成适配器已实现；真实供应商、媒体效果与质量指标尚待配置验证。形象当前为轻量动画，三维/视频及精确口型仍是后续工作。

## 权限与数据要求

沿用项目 OWNER / EDITOR / VIEWER 权限作为管理基线；人物配置发布权限与互动使用权限分别校验。
共享人物配置不等于共享用户的对话或关系记忆。记忆以项目、人物、用户隔离，客户端传入身份不能替代服务端鉴权。
仅使用明确授权材料与平台内用户主动交互；不自动采集私聊或本地 Agent 会话，不访问 Codex sessions。
模型密钥仅保存在服务端或 Worker；日志和审计不记录材料、对话、令牌或模型响应正文。删除记忆时同步处理检索副本；归档、删除和备份保留策略需在实现时定义。

## 核心验收目标（流程已实现，体验质量仍需人工评测）

| 场景 | 预期 |
|---|---|
| 创建与预览 | 可创建原创人物、编辑设定并进行测试对话 |
| 人格一致性 | 多轮情境评测能检查价值观、表达习惯与行为一致性 |
| 情感变化 | 不同交流情境能产生合理变化，调试可追溯使用的状态与上下文 |
| 共同经历 | 用户确认的记忆在后续会话可使用，纠正和删除后不再使用旧内容 |
| 隔离 | 两个用户与两个项目的对话及关系记忆互不泄漏 |
| 版本 | 发布和回滚不覆盖历史，已有对话使用固定版本 |
| 来源 | 授权材料事实有依据，原创设定和推断明确区分 |
| 完整闭环 | 创建 → 预览 → 发布 → 交流 → 记忆管理可通过网页完成 |

人格和情感质量需设计固定情境集并人工评审，流程测试通过不能代替体验质量验收。语音、图像和动态形象分别制定后续验收标准。
