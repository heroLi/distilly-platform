# 文字人格与相关经历稳定性：第一批实现

日期：2026-10-12。目标：“像这个人说话、记得相关经历”。只修改当前平台，保留已有未提交/未跟踪改动；未提交、推送、部署或接入新服务，未使用真实个人材料。

## 已实现与实际边界

1. `MemoryRetrieval` 从当前人物、当前用户的全部 CONFIRMED 记忆中检索，不再先截取最近30条。SQL 同时复核源消息属于该人物与用户的会话；PENDING/REJECTED、其他人物、其他用户不进入候选。中文双字匹配、英文完整词匹配，泛词过滤；先按相关分数，再按时间和ID排序，最多12条。没有词面相关结果时返回空；明确询问“你记得我什么”等才返回记忆概览。它是确定性的词面检索，不是语义模型，尚无同义词、嵌入或重排器。
2. `ExperienceRecall` 只读取当前会话固定人格版本。背景句子分别标记 fictional_setting 或 user_setting_unverified；已校验的材料引句标记 authorized_source_excerpt，不自动声称为人物亲历。复用人格模板时不向目标人物提供模板证据；analysis 推断不作为经历输入。最多8条相关片段。尚未建立独立 PersonaExperience 对象、时间轴或人物事实审核入口。
3. `ContextAssembler` 完整保留固定版本 Markdown、definition、binding 和本轮输入，舍弃聊天不需要的整份分析/证据载荷。近期历史（数据库最多24条）、相关记忆、经历、共享知识使用同一预算；近期少量消息优先保留，相关来源优先于剩余历史。可选条目完整选择或省略，不截断证据正文；人格与本轮输入本身超限时任务 FAILED/CONTEXT_LIMIT，页面显示中文原因。
4. `CHAT_SYSTEM` 明确稳定表达规则、身份边界、共享知识/确认记忆/设定/材料摘录的区别。缺少记录时说明不足，不把“未检索到”说成“从未发生”。输出可选 memory_citations、experience_citations；Worker 与服务端仅接受本轮选择中的ID，服务端复用现有任务载荷保存选中ID和预算诊断，不新增数据库迁移。原 answer/emotion/citations 契约保持。
5. 确认、纠正、删除、关闭记忆仍取消在途旧记忆回复，租约拒绝迟到结果。历史聊天消息仍保持原产品语义；删除长期记忆不等于删除历史消息。

## 预算与配置

- `PLATFORM_CONTEXT_BUDGET_UNITS`：默认65536，允许16384～262144。
- `PLATFORM_REPLY_OUTPUT_TOKENS`：默认2048，允许256～8192；Worker 在 Chat Completions 中设置 max_tokens。
- 文本预算预留8192给系统指令、预留上述输出额度；带图片保留原媒体链路并额外预留8192，但这不是视觉模型精确token验收。
- 输入估计使用 `2 × UTF-8 compact JSON字节数 + 512`，包含元数据；这是可解释的保守文本估计，不是供应商专用 tokenizer。Worker 会复核实际序列化输入与系统指令长度。管理员需按实际模型上下文上限配置，后续可添加对应模型的精确计数器。
- 回复任务结果含 context_budget（输入估计、额度、候选历史/来源省略数量）和所用记忆/经历ID。省略历史数量只针对本次取到的最近24条候选，不表示整段会话总省略量。
